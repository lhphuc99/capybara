`npx capybara-devtools --background` gives the terminal back once Capybara runs, instead of keeping it until Ctrl+C. Capybara keeps running, also after the terminal closes, until `npx capybara-devtools stop`. Its banner says so and names the log file that takes what it prints from then on, such as a device that was turned away or what `CAPYBARA_DEBUG=1` prints. When it cannot start, as when another program holds the port, the command says why and fails, as it does without `--background`, and Ctrl+C while it starts stops it. The setup guide and `capybara mcp` now tell AI assistants to start Capybara this way, so that their shell does not wait on it.

Started without it, Capybara now moves to the background when you press **b** in its terminal. A process cannot give the terminal back and go on, so a new Capybara starts in the background, on the same port and with the same options, and takes over the sessions this one recorded; apps and the UI reconnect on their own. The port is let go only once the sessions are across, for a few milliseconds, so that the desktop app, which takes the port as soon as it is free, does not take it in between. An app with the SDK carries on in its session and sends what it logged in between; an app read through Metro or the Dart VM service shows up as a new session, as after a reload, and its old session keeps what was recorded. The key is read only while Capybara has the terminal, so a Capybara started with `&` is not stopped by the shell. In the terminal, Ctrl+C still stops Capybara, and Enter still leaves an empty line. `createServer` takes the sessions of another server (`sessions`, from its `recorded()`).

Run while a Capybara already has the port, the CLI still opens that one's UI and exits, and now says more about it: that it runs in the background, with its log, which version it is when that is not this one's, as when an older Capybara was left running, and that the desktop app is quit from its menu. Viewers on this computer learn where a server in the background writes its output from `ServerInfo.log`.
